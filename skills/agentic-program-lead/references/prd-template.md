# PRD Template

# <Product / Program Name>

## 1. Executive summary

What is being built, for whom, and why now?

## 2. Problem / opportunity

What problem exists today? What opportunity makes solving it worthwhile?

## 3. Product vision

Describe the intended end state in customer/operator terms.

## 4. Users and actors

For each important actor:

- role/persona;
- goals;
- pain points;
- responsibilities;
- important constraints.

## 5. Primary journeys

Describe the end-to-end journeys that define the product.

For each journey include:

- starting state;
- actor;
- desired outcome;
- major steps;
- important failure/recovery behavior.

## 6. Functional requirements

Group requirements by coherent product capability rather than implementation component.

Use clear identifiers if helpful, e.g. `FR-001`.

## 7. Non-functional requirements

Cover only relevant qualities, such as:

- security;
- isolation;
- availability;
- performance;
- scalability;
- recoverability;
- observability;
- compatibility;
- maintainability;
- accessibility;
- portability.

State observable requirements where possible rather than adjectives.

## 8. Domain and conceptual model

Define important product concepts and distinctions without prescribing class design.

## 9. Product principles

Rules that help resolve ambiguity consistently.

## 10. Constraints

Known technical, commercial, legal, operational, compatibility, or organizational constraints.

## 11. Explicit non-goals

State what is deliberately not required, especially attractive adjacent scope.

## 12. Delivery stages / milestones

For each stage:

- customer/operator outcome;
- minimum included capability;
- explicit exclusions;
- executable success demonstration.

## 13. Success criteria

Define how the program knows the product outcome has been achieved.

Avoid issue-count or code-volume metrics as primary product success criteria.

## 14. Open product decisions

Only include genuinely unresolved choices. Link to the decision log, spike, or ADR as appropriate.
